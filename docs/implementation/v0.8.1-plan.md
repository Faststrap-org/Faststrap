## v0.8.1 Contents

### A. Bug Fixes

#### A1. SimpleToast broken auto-hide animation

**File:** `src/faststrap/components/feedback/toast.py`
**Bug:** The component applies `animation: toastFadeOut 0.5s forwards` via inline style, but no `@keyframes toastFadeOut` exists anywhere in Faststrap CSS. Auto-hide silently does nothing.
**Fix:** Add the keyframe definition. Two options:
- Option 1: Add `@keyframes toastFadeOut` to `src/faststrap/static/faststrap-feedback.css`
- Option 2: Inject the keyframe via a `<Style>` element in the component itself (self-contained)

Recommended: Option 1 (CSS file) — keeps styles centralized.

```css
@keyframes toastFadeOut {
  from { opacity: 1; }
  to { opacity: 0; pointer-events: none; }
}
```

**Tests:** Add test verifying the animation class is applied and the keyframe reference exists.

#### A2. SimpleToast close button non-functional

**File:** `src/faststrap/components/feedback/toast.py`
**Bug:** The close button renders `<button class="btn-close">` but has no onclick handler. In a no-JS context, it does nothing.
**Fix:** Remove the close button entirely from `SimpleToast` (it's the no-JS variant). The close button only makes sense on `Toast` which requires Bootstrap JS.
**Tests:** Verify `SimpleToast(dismissible=True)` does NOT render a close button. Verify `Toast(dismissible=True)` still does.

#### A3. SimpleToast stacking broken

**File:** `src/faststrap/components/feedback/toast.py`
**Bug:** Multiple `SimpleToast` components at the same position all get `position-fixed top-0 end-0` independently — they overlap at the same pixel.
**Fix:** This is a design issue, not a quick fix. For v0.8.1, add a docstring note: "For multiple concurrent toasts, use `ToastContainer` with `Toast` components instead of multiple `SimpleToast` instances." Full stacking logic deferred to v0.9.
**Tests:** No new tests needed (documentation only).

#### A4. ModernToast inline onclick violation

**File:** `src/faststrap/components/feedback/modern_toast.py`
**Bug:** `onclick="this.closest('[data-fs-modern-toast]').remove()"` violates zero-JS philosophy.
**Fix for v0.8.1:** Keep the inline JS for now (it's progressive enhancement, not a blocker). Add a TODO comment in the source: `# TODO(v0.9): Replace with HTMX hx-on:click or CSS-only dismiss`. Full rebuild deferred to v0.9.
**Tests:** No change needed.

#### A5. ModernToast hardcoded z-index

**File:** `src/faststrap/components/feedback/modern_toast.py`
**Bug:** `"style": "z-index: 1080;"` is hardcoded in `ModernToastStack`.
**Fix:** Change to use a CSS variable with fallback: `style="z-index: var(--fs-toast-z-index, 1080);"`. This allows theme customization.
**Tests:** Verify the style attribute contains the CSS variable reference.

### B. New Components (5 native, zero-JS)

#### B1. Separator

**File:** `src/faststrap/components/layout/separator.py`
**Category:** layout
**Complexity:** Trivial (5 lines of logic)
**JS Required:** No

```python
@register(category="layout")
@stable
def Separator(
    *,
    orientation: Literal["horizontal", "vertical"] = "horizontal",
    thickness: int | None = None,
    spacing: int | None = None,
    label: str | None = None,
    **kwargs: Any,
) -> Div:
    """Render a semantic separator/divider.
    
    orientation: horizontal (default) or vertical
    thickness: border width in px (default: 1 for horizontal, 1 for vertical)
    spacing: margin y (horizontal) or margin x (vertical) in Bootstrap spacing units
    label: optional text label centered on the divider (like <fieldset><legend>)
    """
```

**Implementation notes:**
- Horizontal: `<hr>` with Bootstrap `border-top` classes, or `<div>` with `border-top`
- Vertical: `<div>` with `border-start` + `h-100` or explicit height
- Label variant: Use `<div>` with `position: relative` and centered `<span>` with background color to create the "line through text" effect
- Reuse: Should integrate with existing Bootstrap utility classes

**Tests:** 10+ tests covering orientation, thickness, spacing, label, custom classes, accessibility (role="separator", aria-orientation)

#### B3. OTPInput

**File:** `src/faststrap/components/forms/otp_input.py`
**Category:** forms
**Complexity:** Low-Medium (CSS-only, but needs careful input handling)
**JS Required:** No (CSS-only auto-advance via ` maxlength="1"` + `inputmode="numeric"`)

```python
@register(category="forms")
@stable
def OTPInput(
    length: int = 6,
    *,
    name: str = "otp",
    variant: VariantType = "primary",
    size: Literal["sm", "md", "lg"] = "md",
    gap: int = 2,
    autofocus: bool = True,
    **kwargs: Any,
) -> Div:
    """Render a CSS-only OTP/pin input with individual digit boxes.
    
    Each box accepts one digit. Uses inputmode="numeric" for mobile keyboards.
    Auto-advances focus on input (CSS :focus-within + maxlength="1").
    Posts all digits under the given `name` as a single concatenated string.
    """
```

**Implementation notes:**
- Render `length` individual `<input>` elements, each with `maxlength="1"`, `inputmode="numeric"`, `pattern="[0-9]"`
- Wrap in a flex container with configurable gap
- Each input gets Bootstrap form control styling
- Hidden `<input>` with `name` that collects all digits (or use HTMX to concatenate)
- CSS-only auto-advance: On `input` event, if value.length === 1, focus next sibling. This needs one line of JS or HTMX — mark as `requires_js=True` if JS is needed, or use `hx-post` to handle server-side.
- Alternative: Use a single `<input type="text" pattern="\d{6}" maxlength="6">` with CSS `letter-spacing` and `caret-color` tricks for a single-field OTP. Simpler, truly zero-JS.

**Decision needed:** Single-field (truly zero-JS) vs multi-field (needs 1 line of JS for auto-advance). Recommend single-field for v0.8.1 to stay zero-JS.

**Tests:** 15+ tests covering length variants, name attribute, inputmode, maxlength, pattern, accessibility (autocomplete="one-time-code")

#### B4. AspectRatio

**File:** `src/faststrap/components/layout/aspect_ratio.py`
**Category:** layout
**Complexity:** Trivial (CSS wrapper)
**JS Required:** No

```python
@register(category="layout")
@stable
def AspectRatio(
    children: Any,
    *,
    ratio: str = "16/9",
    **kwargs: Any,
) -> Div:
    """Render content in a responsive aspect ratio container.
    
    Uses CSS `aspect-ratio` property. Children fill the container.
    Common ratios: "16/9", "4/3", "1/1", "21/9"
    """
```

**Implementation notes:**
- Single `<div>` with `style="aspect-ratio: {ratio};"` and `overflow: hidden`
- Children get `width: 100%; height: 100%; object-fit: cover;` for media
- CSS `aspect-ratio` is supported in all modern browsers (97%+ global support)
- Fallback: `padding-top` trick for old browsers (optional, can skip for v0.8.1)

**Tests:** 10+ tests covering ratio values, custom classes, child content, overflow behavior

#### B5. Tag / Chip

**File:** `src/faststrap/components/display/tag.py`
**Category:** display
**Complexity:** Low (styled badge variant with close button)
**JS Required:** No (close button is decorative; actual removal needs HTMX or JS)

```python
@register(category="display")
@stable
def Tag(
    children: str | tuple,
    *,
    variant: VariantType = "secondary",
    size: Literal["sm", "md"] = "md",
    removable: bool = False,
    icon: str | None = None,
    on_remove: str | None = None,  # HTMX attribute for removal
    **kwargs: Any,
) -> Span:
    """Render a tag/chip component.
    
    Different from Badge: Tags are interactive, often removable, and used for
    filtering/labeling. Badge is purely informational.
    """
```

**Implementation notes:**
- Use `<span>` with Bootstrap badge classes as base, override with tag-specific CSS
- Removable variant adds a small × button (like `btn-close` but inline)
- `on_remove` parameter accepts an HTMX attribute string for server-side removal
- Icon slot for optional leading icon
- Should look distinct from Badge — more padding, rounded-full, interactive hover state

**Tests:** 15+ tests covering variants, sizes, removable flag, icon, on_remove, custom classes, accessibility
